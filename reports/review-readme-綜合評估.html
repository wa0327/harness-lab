給 harness-lab 的附帶發現

  • 本地模型的審查錯誤率偏高：每份報告有 1–3 條錯誤或捏造，大多是「README 已經寫了卻說沒寫」或「沒查證就下結論」。拿本地模型做文件審查，結論一定要人工核對。
  • 單次結果不足以比較 harness：建議每位考生跑 3 次取平均，報告改成「平均分數 ± 範圍」。
  • 這一題的鑑別力不錯：第 2、4、8 條所有考生都漏了，第 11–15 條只有 Claude 抓到，可以留著比較日後的模型或設定。

結論

本地組四位都待在快照內，在 2–3 分鐘內交出報告，分數落在 46–57 之間。差距主要是有沒有認真探索專案：Codex、Qwen Code 讀了腳本和設定，抓到的是專案特有的問題；Pi、OpenCode 讀得少，寫出來的就是放到哪裡都成立的通用清單。

Claude 和本地組的差距很明顯：覆蓋 21 對 1–5，錯誤 0 對 1–3。這是模型能力的差距，換 harness 補不回來。ds4 組跑完後，可以看出更強的模型搭配這幾個 harness 能把差距縮小多少。
